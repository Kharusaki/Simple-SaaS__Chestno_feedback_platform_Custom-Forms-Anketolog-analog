## 1. Что это

Учебный проект по ТЗ «Задание 9. Мини-SaaS для опросов» (★★★★).
Оригинал ТЗ лежит в корне репозитория:
`Задание 9. Мини-SaaS для опросов ⭐⭐⭐⭐.txt`.

**Сервис, который создаёт опросы с уникальными ссылками, собирает ответы и
показывает статистику.** Заменяет Google Forms для простых сценариев:
создатель делает опрос → респонденты проходят по ссылке без регистрации →
результаты собираются автоматически.

**Режим работы:** выполняется одним заходом в два этапа. Рубежи, на которых
подключается пользователь, — **A: usable MVP** (после Фазы D) и **B: сдача**
(после Фазы F). Подробности в `PLAN.md`.

## 4. Ключевые продуктовые решения (согласованы с пользователем)

1. **Авторизация: учётные записи с ролями.** Ровно две роли: `admin` и
   `creator`. Респондент учётной записи не имеет и не заводит.
   Почему отказались от анонимного владельца: cookie выдавалась сама при
   первом заходе на `/dashboard` и открывала пустую анкету кому угодно, а
   «владелец» определялся первым же заходу. Теперь `User` появляется только
   через регистрацию или вход, а сессия в cookie хранит лишь `id`.
2. **Ссылка — настоящая, генерируемая.** `slug` = 8 знаков из алфавита
   `abcdefghijkmnpqrstuvwxyz23456789` (без похожих `0/o/1/l`), проверка
   уникальности с ретраями. Путь: `/s/{slug}`. Плюс ссылка-ключ
   `/k/{token}` для передачи доступа к статистике коллеге.
3. **Пять типов вопросов:** `single`, `multiple`, `yes_no`, `scale` (1–5 / 1–10),
   `text`. Все пять обязательны к приёмке — выбраны пользователем.
4. **Публичная часть не требует ничего:** `/s/{slug}` открыта всем, кто имеет
   ссылку. Регистрация/капча отсутствуют.
5. **Приватная часть:** `/s/{slug}/stats` требует `?key=<token>` из `survey_keys`
   **или** валидную владельческую сессию. Токены сравниваются
   `secrets.compare_digest`.
6. **Redis опционален.** Приложение полностью работоспособно без него:
   кэш статистики и rate-limit переключаются на process-local реализацию.
7. **Основной ключ и право правки — разные вещи.** Основной ключ опознаётся
   по зарезервированной метке `surveys/crud.py: PRIMARY_KEY_LABEL`, а не по
   `can_edit=True`: иначе дополнительный ключ с правом правки нельзя было бы
   отозвать и он выглядел бы в таблице как основной. Метка защищена от
   повторного использования, `revoke_key()` отказывает только по ней самой.
8. **Ключ с правом правки ограниченнее владельца.** Он правит структуру и
   тексты, но не видит остальные ключи, не меняет `is_open` и не удаляет
   анкету: в форме правки `is_open` применяется только при входе по cookie.
9. **Лимиты считаются по хешу, а не по IP.** `utils.client_fingerprint()` —
   sha256 от адреса и `SECRET_KEY`: сырой адрес не попадает ни в ключи
   кэша, ни в логи.
10. **Ответы респондента личные, кабинет владельца — нет.** Респонденту
    показывается баннер «Вы уже заполнили эту анкету», его собственные ответы
    и страница `/my`. В навигации у него только «Мои ответы», а `/dashboard`
    перенаправляет на `/my`. Проверка идёт **до** `get_or_create_current_user()`,
    иначе каждый заход респондента создавал бы пустого `User`.
11. **Идентичность респондента — отдельная cookie, не владельческая.**
    `respondent_id` (httpOnly, год) хранит случайный токен. В `responses`
    пишутся `respondent_token` (основной путь, переживает смену IP и UA) и
    `respondent_hash` (запасной путь и совместимость со старыми записями).
    Навигация скрывается по наличию owner-cookie: cookie `respondent_id` не
    должна превращать респондента во «владельца без анкет».
12. **Форма остаётся видимой после ответа.** Кнопку отправки убираем, но поля
    не прячем: человек видит, что анкета уже заполнена, и может перечитать
    свои ответы. Повторный `POST` отдаёт 409, а не 200.
13. **`MODERATOR_TOKEN` больше не существует.** Модератор заменён ролью `admin`
     в `User`. Раздел `/admin` и его подразделы отдают **404** неадминистратору
     (существование раздела не подтверждается постороннему) и **303** на
     форму входа гостю, причём даже на `POST` с файлом: файл не сохраняется.
     Учётка заводится сама при первом запуске из `ADMIN_USERNAME` /
     `ADMIN_PASSWORD`, и повторный запуск её не трогает. Вход по `MODERATOR_TOKEN`
     и `moderation/` удалены вместе с `auth/tokens.py`.
14. **Картинки определяются по содержимому, а не по имени.** Magic bytes,
    серверное имя `secrets.token_hex(12)`, лимит 2 МБ, расширение из
    содержимого. **SVG не принимается** — он исполняет JS, а файлы отдаются
    с того же origin, что и страницы (stored XSS). Разрешены PNG, JPEG,
    WebP, GIF.
14a. **Картинка вопроса — по номеру блока, а не по позиции.** `_question_images()`
    в `surveys/router.py` отдаёт словарь `номер блока → файл`, и CRUD берёт
    картинку по `enumerate(payload.questions)`. Нельзя сводить к позиции среди
    непустых вопросов: пустой блок сдвинул бы картинку на соседний вопрос.
    `create_survey` / `update_survey` стали `async` из-за файлов; откат не
    ограничивается `UploadError` — `RuntimeError` в тестах закрывает транзакцию
    вручную, и `test_create_survey_rolls_back_on_failure` это проверяет.
14b. **Сохранённую картинку вопроса нельзя подменить формой.** `qN_image_keep`
    приходит от клиента, поэтому `update_survey` сверяет значение со списком
    файлов этой анкеты. Подделанное имя игнорируется, поле очищается.
14c. **Файл удаляется только после успешной записи нового** (`images.replace_image`),
    иначе неудачная загрузка оставила бы поле без картинки. При откате
    транзакции снимаются и файлы, успевшие записаться на диск.
15. **Настройки оформления — одна строка `site_settings` (id=1).** В ней
    только имена файлов в `media/`, не сами байты, поэтому база не растёт от
    картинок. Замена картинки удаляет старую с диска. Удаление анкеты тоже
    убирает обложку: `surveys/crud.py: delete_survey()` вызывает `delete_image()`
    **до** удаления записи из БД.
16. **Публичная документация API закрыта.** `/docs`, `/redoc` и
    `/openapi.json` отдают 404 всем, включая администратора: они описывают
    закрытые процессы. Схема доступна администратору на `/admin/openapi.json`.
    Страницы-обёртки для неё больше нет: `/admin/api` удалён, ссылка на схему
    лежит в `README.md`.
16a. **Тема и шрифт анкеты — `themes.py`, а не шаблон.** `Survey.theme` и
    `Survey.font` хранят ключи из белых списков, а `theme_css()` подставляет
    `--survey-accent`, `--survey-bg`, `--survey-text` в `<style>` на публичной
    странице. Незнакомое значение молча игнорируется, в базу мусор не попадает.
    Список ключей и значения по умолчанию — в `THEME_CHOICES` / `FONT_CHOICES`.
16b. **График статистики рисуется только если загрузился Chart.js.** Блок
    `chart-box` скрыт в разметке, а `static/js/stats_charts.js` его
    показывает. Библиотека приходит с CDN, и без сети пустой канвас выглядел бы
    как сломанная страница. Связь с вопросом идёт по `question_id` в JSON из
    Jinja — список в разметке и список в данных обязаны совпадать, это
    проверяет `tests/test_stats_charts.py`.
16c. **Текст ошибки принадлежит конкретному полю.** Отказ по картинке вопроса
    приходит как `UploadError(question_index=...)` и показывается в этом блоке,
    а не у обложки. Скрытый `<template>` нового вопроса рендерится с пустым
    словарём ошибок, иначе клон утащил бы чужой текст.
17. **Отказ от доступа поднимается исключением, а не редиректом.**
    `require_user` бросает `LoginRequired` (303 с `?next=`), `require_admin` —
    `SectionHidden` (404). Иначе зависимостью «вернулось» бы не `User`, а
    HTTP-ответ. `next` собирается из самого запроса в `return_target()`, а не
    берётся из параметра: иначе `/login` стал бы открытым редиректом.
18. **Пароль администратора по умолчанию — намеренный.** Учётка создаётся с
    `must_change_password=True`, после входа на каждой странице открывается
    модальное окно «У вас стандартный пароль». Два действия различаются:
    - «Продолжить как есть» ставит cookie `pw_notice_off` на 8 часов
      (`settings.password_notice_max_age`) и **не трогает** флаг в базе —
      предупреждение вернётся на другом компьютере;
    - «Не напоминать больше» снимает `must_change_password` навсегда.
    Смена пароля и выход чистят cookie. Значения `ADMIN_USERNAME`/
    `ADMIN_PASSWORD` читаются **только** при создании учётки и в лог
    не попадают.
19. **Логин: латиница, цифры, `_`, `-`, `.`, 3–64 символа, сравнение без учёта
    регистра, `admin` зарезервирован.** Пароль хранится как
    PBKDF2-HMAC-SHA256, 600 000 итераций, соль на пользователя
    (`auth/passwords.py`).

## 6. Схема базы данных

SQLite, файл `survey.db` в корне (переопределяется `DATABASE_URL`).
Все связи `ON DELETE CASCADE`, `PRAGMA foreign_keys=ON` при старте.

```
users
  id                   INTEGER PK
  username             VARCHAR(64) UNIQUE NOT NULL  -- латиница, 3-64, 'admin' резерв
  password_hash        VARCHAR(255) NOT NULL       -- PBKDF2-HMAC-SHA256, 600k итераций
  is_admin             BOOLEAN NOT NULL DEFAULT 0
  must_change_password BOOLEAN NOT NULL DEFAULT 0
  created_at           DATETIME NOT NULL
  -- Анонимного владельца больше нет: User создаётся только регистрацией
  -- или входом, поэтому заход на страницу никого не плодит.
  -- В cookie сессии лежит только подписанный id, не токен и не пароль.

surveys
  id           INTEGER PK
  slug         VARCHAR(8)  UNIQUE NOT NULL     -- /s/{slug}, генерируется
  owner_id     INTEGER FK -> users.id, CASCADE
  title        VARCHAR(200) NOT NULL
  description TEXT NULL
  cover_image  VARCHAR(200) NULL               -- имя файла в media/
  theme        VARCHAR(16) NOT NULL DEFAULT 'light'   -- см. themes.py
  font         VARCHAR(16) NOT NULL DEFAULT 'system'  -- см. themes.py
  review_mode  VARCHAR(16) NOT NULL DEFAULT 'none'    -- none|score|explain
  is_open      BOOLEAN NOT NULL DEFAULT 1      -- 0 = опрос закрыт для ответов
  created_at   DATETIME NOT NULL
  updated_at   DATETIME NOT NULL
  -- review_mode — режим проверки ответов, один на всю анкету:
  --   none    — проверки нет, респондент видит только благодарность
  --   score   — показывается «N из M»
  --   explain — балл, разбор по вопросам и пояснение к правильному ответу
  -- relations: questions[], choices[] (через вопросы), responses[], survey_keys[]

questions
  id          INTEGER PK
  survey_id   INTEGER FK -> surveys.id, CASCADE
  position    INTEGER NOT NULL                 -- порядок показа
  text        VARCHAR(500) NOT NULL
  type        VARCHAR(16) NOT NULL              -- single|multiple|yes_no|scale|text
  is_required BOOLEAN NOT NULL DEFAULT 1
  scale_min   INTEGER NULL                     -- только для type=scale
  scale_max   INTEGER NULL
  image       VARCHAR(200) NULL                -- имя файла в media/
  explanation VARCHAR(1000) NULL               -- показывается в режиме explain
  correct_value_text VARCHAR(300) NULL         -- верный ответ для yes_no
  correct_value_int  INTEGER NULL              -- верное значение шкалы
  -- Свободный текст не оценивается: correct_* для type=text всегда NULL.

choices                                     -- варианты ответа
  id          INTEGER PK
  question_id INTEGER FK -> questions.id, CASCADE
  position    INTEGER NOT NULL
  text        VARCHAR(300) NOT NULL
  is_correct  BOOLEAN NOT NULL DEFAULT 0      -- верный вариант
  -- правило: choices обязательны для single/multiple; не нужны для
  -- yes_no (подставляются «Да»/«Нет»), text, scale

responses                                   -- одна сессия прохождения
  id               INTEGER PK
  survey_id        INTEGER FK -> surveys.id, CASCADE
  started_at       DATETIME NOT NULL
  submitted_at     DATETIME NULL              -- NULL = не завершена
  respondent_token VARCHAR(64) NULL           -- токен cookie respondent_id
  respondent_hash  VARCHAR(64) NULL           -- sha256(ip+ua), анти-дубли + legacy
  -- Оба идентификатора nullable: ответы, сделанные до появления cookie,
  -- остаются в базе. Поиск «моих ответов» идёт по токену, при его отсутствии
  -- у респондента — по хешу.

answers                                    -- один ряд на один ответ
  id          INTEGER PK
  response_id INTEGER FK -> responses.id, CASCADE
  question_id INTEGER FK -> questions.id, CASCADE
  kind        VARCHAR(16) NOT NULL           -- тип вопроса | 'skipped'
  value_text  TEXT NULL                      -- text, single, yes_no, multiple
  value_int   INTEGER NULL                   -- scale

survey_keys                                 -- доступ к статистике и правке
  id          INTEGER PK
  survey_id   INTEGER FK -> surveys.id, CASCADE
  token       VARCHAR(64) UNIQUE NOT NULL    -- секрет 48 символов, /k/{token}
  label       VARCHAR(100) NOT NULL          -- 'основной доступ', 'для коллеги'
```

## 8. Правила валидации ответов

- `single`, `yes_no` — ровно одно значение, `value_text` берётся из
  существующего `choices`/`questions`, иначе поле игнорируется.
- `multiple` — ноль и более значений, каждое сверяется с `choices`;
  строки добавляются по одной на вариант (`kind='multiple'`).
- `scale` — целое в `[scale_min, scale_max]`, иначе `skipped`.
- `text` — обрезается до 2000 символов, пустая строка → `skipped`.
- Любой невалидный/отсутствующий ответ **не ломает отправку**: пишется `skipped`.
- Если опрос закрыт (`is_open=0`) — 403 со страницей-заглушкой.
- Если по `respondent_hash` есть завершённый ответ — 409, повтор запрещён.

### Правила подсчёта балла

Балл считает `surveys/review.py` по ответам конкретного респондента, а не по
статистике: `/s/{slug}/thanks` показывает оценку именно его ответов.

- **Оцениваются не все вопросы.** В зачёт идут только `single`, `multiple`,
  `yes_no` и `scale`, у которых отмечен правильный ответ. Текст и вопросы без
  отметки пропускаются, иначе знаменатель «из 5» врал бы респонденту.
- **`multiple` требует полного совпадения набора** правильных вариантов.
  Частично верный набор балла не даёт.
- **`single` и `yes_no`** сверяются по тексту, **`scale`** — по числу.
- **`review_mode='none'`** не считает ничего и не показывает разбор.
- **Разбор не показывается до отправки**: на `/s/{slug}` правильных ответов и
  пояснений в разметке нет.

Создать анкету с режимом проверки, когда оценивать нечего, нельзя: форма
отвечает ошибкой. Иначе респондент получил бы пустую страницу итога.

### Встроенные шаблоны

`surveys/presets.py` хранит три готовых анкеты: удовлетворённость, после
покупки, тест знаний. Шаблон **только заполняет форму** — отдельного пути
создания нет, анкета всегда собирается из формы обычным разбором. Поэтому шаблон
легко правится и не может разойтись с логикой конструктора.

Правильные ответы хранятся **текстом варианта, а не его id**. Смена текста
варианта разрывает связь: привязка по id потребовала бы переписывать
статистику при каждом редактировании вопроса.

## 9. Redis

Переменные: `REDIS_URL` (по умолчанию пусто → in-memory), `REDIS_TTL_SECONDS=30`.

Используется для двух вещей:

- **кэш агрегатов статистики**, ключ `stats:{slug}`. Агрегаты сначала
  сводятся в JSON (`analytics/service.py: stats_to_payload`), на попадании
  собираются обратно (`stats_from_payload`) **без запросов к базы** — поэтому
  попадание в кэш не тянет за собой сессию SQLAlchemy. Кэш сбрасывается явно
  после нового ответа, правки анкеты и её удаления, а TTL служит страховкой;
- **лимиты частоты**, ключ `rate:{корзина}:{отпечаток}:{окно}`, где окно —
  `int(time.time()) // период`. Корзины: `create` = 20/час, `submit` = 10/мин,
  `page` = 300/мин.

В лимитах используется не IP, а `utils.client_fingerprint()` — sha256 от адреса
и `SECRET_KEY`, обрезанный до 32 символов. Сырой адрес не попадает ни в ключи
Redis, ни в process-local словарь, ни в логи.

**Контракт:** `analytics/cache.py` — единственная точка доступа. Никогда не
импортируй `redis` вне этого модуля. Бэкенд выбирается один раз при первом
обращении: `REDIS_URL` пуст или Redis не отвечает — берётся `MemoryBackend`
с тем же контрактом `get/set/delete/increment/ping`. Любая ошибка Redis после
этого даёт warning и промах кэша, но не исключение наружу: битый JSON
удаляется и считается промахом, неработающий счётчик лимитов пропускает
запрос. Redis не должен быть обязательным ни для старта, ни для работы,
ни для тестов.

Проверить выбранный бэкенд: `GET /health/redis` →
`{configured, backend, available, ttl_seconds}`.

## 10. Тестирование

`pytest` с `TestClient`, фикстура на **отдельный файл SQLite**
(`test_survey.db`, не общая БД), env-переменные теста выставляются в
`conftest.py` **до** импорта `main`.

Обязательные сценарии: создание анкеты, уникальность slug, публичное
прохождение, сохранение всех 5 типов, валидация, закрытая анкета, анти-дубль,
защита статистики (с ключом / без / чужой), права ключей, отзыв ключа,
запрет editor-ключу менять приём ответов, кэш hit/miss и сброс, фолбэк без
Redis, битая запись кэша, лимиты и 429, CSV, каскадное удаление.

Для приватности респондента (`tests/test_respondent.py`): выдача cookie,
баннер после ответа, показ своих ответов, страница `/my`, скрытие «Моих
анкет», редирект `/dashboard → /my`, запрет статистики, анти-дубль по токену
и по хешу, поведение при потере cookie (не должен отдавать чужие ответы).

Для учётных записей и прав (`tests/test_access.py`, `tests/test_admin.py`):
регистрация и дубли логинов, вход с неверным паролем, `303` гостя с
`?next=`, возврат на `next` после входа, `404` неадминистратору на `/admin`,
закрытость `/docs` для всех, админ-схема на `/admin/openapi.json`, seed
администратора из `.env`, повторный запуск не сбрасывает пароль, отказ от
смены пароля, загрузки в `/admin` каждого разрешённого формата, отклонение SVG,
`nosniff` в `/media`.

Состояние ролей задаёт тест, а не содержимое `.env` на диске: фикстуры в
`conftest.py` создают администратора явно. Без них тесты зависели бы от
локального файла разработчика.

Для лаунчера (`tests/test_launcher.py`): занятость порта и её стабильность
на повторах, освобождение порта после закрытия сокета, подбор соседнего
свободного порта, отказ запуска при занятом порте, `EOFError` на закрытом
stdin, подготовка БД и вызов `uvicorn.run`, ссылки в баннере, безопасность
`webbrowser.open` и **побайтовая ASCII-проверка `start.bat`**.

Три особенности настройки тестов, которые легко упустить:

- **Лимиты частоты в тестах выключены** через
  `RATE_LIMIT_*=0` в `conftest.py`. Счётчики живут в памяти процесса, и
  иначе копились бы между тестами, ломая их по нарастающей.
- **Кэш сбрасывается автофикстурой** `_fresh_cache` до и после каждого
  теста, иначе закешированная статистика протекала бы из теста в тест.
  Redis проверяется подставным клиентом `FakeRedis`, а не настоящим сервером.
- **Cookie респондента сбрасывается между тестами лимитов.** Иначе второй
  «респондент» в тесте оказался бы тем же человеком по cookie, а не новым
  по IP+User-Agent, и проверка анти-дубля врала бы.
- **Параллельный прогон даёт каждому воркеру свою базу.** Под `pytest -n`
  воркеры идут параллельно и бьют по общему файлу: Windows сообщает об этом
  блокировкой, и падает не код, а его проверка. `conftest.py` берёт имя из
  `PYTEST_XDIST_WORKER` и подставляет `test_survey<worker>.db`; без флага
  переменной нет и путь остаётся прежним.

**Проверка внутри этапов обязательна:** каждая фаза завершается зелёным
`pytest` и новыми тестами на её код. Фазу без тестов завершённой не считать.
Рабочий запуск: `pytest -q -n 8` (481 тест, ~50 s вместо ~3 min).
Текущее состояние: **481 passed**.

### Живой прогон `scripts/smoke.py`

Поднимает настоящий сервер на свободном порту и ходит по нему HTTP.
Три детали, каждая из которых уже стоила прогона:

- **Своя база.** Сервер поднимается на `_smoke.db`, а не на рабочей
  `survey.db`, и база удаляется в `finally` после `engine.dispose()`:
  иначе прогоны копят анкеты и пользователей, а на Windows файл остаётся
  занятым и `unlink` даёт PermissionError, который проглатывает `sys.exit`.
- **Логин smoke не должен совпадать с логином в `.env`.** Сервер и smoke
  поднимаются с одним `ADMIN_*`, поэтому сценарий использует собственное имя
  вроде `smoke_owner` и убирает его в конце, иначе повторный прогон падал бы
  на «логин уже занят».
- **Позиция вопроса ≠ его id.** У `fieldset` стоит `id="q<id вопроса в
  базе>"`, а разбирать ответы нужно по имени поля `q<id>`. Маппинг строится
  по порядку следования; на непустой базе id не начинаются с единицы.

## 11. Ограничения окружения

- Путь проекта содержит кириллицу и эмодзи → **всегда** `$env:PYTHONIOENCODING="utf-8"`.
- **`start.bat` обязан оставаться ASCII.** `cmd.exe` читает пакетные файлы
  в системной кодировке, и русская строка внутри превращается в команды,
  которые он пытается выполнить, а кириллица в пути рассыпается на `?`.
  Сообщения для пользователя печатает `scripts/launcher.py`. Следит
  `tests/test_launcher.py::TestStartBatchIsAscii`.
- **Занятость порта проверяется через `bind`, а не `connect_ex`.** На
  Windows подключение к незанятому порту возвращает WSAEWOULDBLOCK и
  оставляет сокет в полуоткрытом состоянии, из-за чего повторная проверка
  того же порта даёт противоположный ответ. `SO_REUSEADDR` не выставляется:
  на Windows он позволяет перехватить чужой слушающий сокет.
- Git-репозиторий создан **внутри папки проекта** (не в `C:\Users\user`).
  В домашней папке есть чужой repo без коммитов — не путать.
- `redis-server` на машине **не установлен**; в Docker он есть.
  Локальный запуск всегда проверяет фолбэк-путь.
- Скриншоты тестовых прогонов делает пользователь сам, агент не тратит на них время.
- **Браузера в окружении нет.** Фоновую картинку, логотип, мобильную вёрстку
  и `docs/stats.png` проверить автоматически нельзя. Всё, что видно глазом,
  вынесено в ручную проверку. Известный подозрительный момент: слой фона
  `body::before` с `z-index: -1` может перекрываться непрозрачным
  `background: var(--bg)` у `body` — проверить в браузере.
- **Миграций в привычном виде нет, но апгрейд схемы есть.**
  `create_all()` не добавляет колонки в существующую базу, поэтому
  `database/init_db.py` содержит `add_missing_columns()`: он смотрит
  `PRAGMA table_info` и делает `ALTER TABLE ... ADD COLUMN` для тех колонок,
  которых нет, со значениями по умолчанию из моделей. Данные не трогает.
  Важно для `survey.db` в этой папке: там ручные анкеты, а `--drop` запрещён.

## 12. Что НЕ делаем (за границами проекта)

E-mail отправка, восстановление пароля, мультиязычность, API для внешних
интеграций, платежи, drag-and-drop сортировка, сложные логические условия
(показать вопрос по ответу), экспорт в PDF. CSRF-токенов нет: защита держится
на `SameSite=Lax`, для публичного интернета этого недостаточно — это
ограничение, а не решение.

Про оформление сознательно не делаем: отдельный фон по анкетам, галерея
загруженных файлов, сборщик мусора по осиротевшим картинкам в `media/`,
обрезка и ресайз изображений. Темы и шрифты анкет уже есть — пять тем и
четыре шрифта, это перекрывает простую потребность в «тёмной анкете»
без отдельного конструктора.
